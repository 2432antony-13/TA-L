# TA-L

**讓一次抽牌，成為整理問題、理解自己和繼續對話的入口。**

TA-L 是結合手勢抽牌、三牌陣與 AI 對話的塔羅體驗。使用者可以圍繞一個具體問題，選擇理性或共情的回應風格，透過牌面敘事觀察過去、現在與未來的不同角度，再用追問把模糊感受整理成可以考慮的行動。夜色、星光與牌面動畫服務於沉浸體驗，產品定位是娛樂與自我反思。

## 適合誰使用

- 想借助牌面敘事整理問題、探索想法與感受的使用者。
- 偏好理性分析或溫和共情，希望選擇回應方式的體驗者。
- 研究手勢互動、卡牌動畫和流式 AI 對話的開發者。

## 7 個核心功能

### 1. 完整牌庫與三牌陣

從 78 張塔羅牌中抽取三張不重複的牌，包含正位與逆位，並以過去、現在、未來三個位置呈現。 在同一問題下得到一組有位置關係的牌面，而不是三段互不關聯的隨機說明。

**目前：** 牌庫、抽取和揭牌流程已實現。

### 2. 手勢、鍵鼠多種抽牌方式

可開啟攝影機，用指向、移動和握拳等手勢參與選牌；也保留滑鼠和鍵盤入口，配合洗牌與翻牌動畫。 按裝置條件選擇互動方式，不開啟攝影機也能完成抽牌。

**目前：** 手勢在瀏覽器本地識別；需攝影機授權。

### 3. 理性與共情兩種回應風格

在開始前選擇偏重邏輯與行動建議的理性風格，或側重感受梳理與溫和表達的共情風格。 同一套牌面可以用更適合當前需求的表達方式展開，選擇會傳入解讀與追問上下文。

**目前：** 已實現；風格選擇不構成人格診斷。

### 4. 可跳過的偏好訪談

透過 10 道選擇題描述思考和應對問題的偏好，形成用於本次體驗的偏好輪廓；也可以跳過，直接進入問題與抽牌。 讓解讀參考使用者主動提供的偏好，偏好輪廓按語言儲存在當前瀏覽器，後續可檢視或重新進行。

**目前：** 訪談已實現；模型偏好輪廓需伺服器端配置，請求失敗或輸出格式不符時回退至本機規則產生的偏好輪廓。

### 5. AI 流式解讀

把問題、牌位、正逆位、回應風格和可選偏好輪廓交給伺服器端模型，逐段顯示正文，並處理載入、失敗與重試。 閱讀圍繞本次牌陣展開的解釋與條件性建議，正文不展示模型的隱藏推理內容。

**目前：** 需要伺服器端模型金鑰；新解讀使用所選語言。

### 6. 結合上下文的繼續追問

初次解讀後可選建議問題或輸入自己的問題，保留原始問題、牌陣與已有解讀作為上下文，最多繼續三輪。 把某個具體想法問清楚，無須重新抽牌；流式追問支援取消，失敗後可重試。

**目前：** 已實現；依賴解讀服務，追問儲存另依賴歷史儲存。

### 7. 裝置級歷史回看

配置 Redis 後儲存問題、牌面、回應風格、解讀與追問，歷史側欄按當前裝置識別碼讀取最近記錄並展開檢視。 回顧自己此前提出的問題和獲得的回應；當前介面展示最近 20 條，儲存保留最近 50 條。

**目前：** 需配置歷史儲存；裝置識別碼不等於帳號認證或跨裝置同步。

## 從開始到結果

1. 選擇簡體中文、繁體中文或 English，再選擇理性或共情風格。
2. 完成或跳過偏好訪談，輸入一個希望整理的具體問題。
3. 用手勢或鍵鼠抽取並揭開三張牌，等待流式解讀。
4. 針對關心的細節繼續追問；儲存已配置時，可在歷史側欄回看。

## 目前完成程度

- 可執行的產品原型，已有公開體驗入口；程式碼覆蓋抽牌、訪談、解讀、追問與裝置級歷史。
- AI 解讀與模型產生的偏好輪廓需要伺服器端金鑰；偏好輪廓請求失敗或輸出格式不符時，使用本機規則產生的偏好輪廓。歷史需要 Redis，單獨啟動前端不等於這些外部服務已經可用。
- 介面、牌面文字與新解讀請求支援三語；已有歷史內容保持生成時的語言。

## 快速開始

Node.js 22。複製 .env.example 為 .env.local，在伺服器端填寫 DEEPSEEK_API_KEY；歷史功能另需 Redis 配置。普通 Vite 開發服務提供解讀代理，歷史 API 需相應伺服器端執行環境。

```bash
npm ci
# Copy .env.example to .env.local
# Set DEEPSEEK_API_KEY on the server
npm run dev
# http://localhost:5176
npm run lint
npm test
npm run build
```

## 使用邊界

- 牌面用於娛樂與反思，不能確認未來事件或替代專業判斷；表達應區分使用者事實、牌面象徵和條件性建議。
- 攝影機畫面在瀏覽器本地用於手勢識別；發起 AI 請求時，問題、牌陣及所選偏好會傳送到伺服器端與模型服務。
- 裝置識別碼不是身份認證；沒有配置 Redis 時，歷史介面不會提供持久化。
